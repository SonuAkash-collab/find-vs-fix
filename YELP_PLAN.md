# Yelp: the name shortcut on a second dataset (exploratory, not pre-registered)

Status: this plan was written on 11 Nov 2026 before any Yelp run, but it was committed together with the results, so it
does not meet hard rule 2 (rule committed before the run). Report Yelp as exploratory. The run used the shared code at
commit a158eb5 (sha256 of every file in CODE_MANIFEST.json; later commits changed src/common.py, src/checks.py and
src/retrain.py for Phase 5b). The source hashes in results/yelp/imdb_reference.json were taken from Windows copies with
CRLF line endings; regenerating that file from the committed (LF) files gives identical values.

Question: does the IMDB name shortcut, and the Phase 3c result (retraining any single block removes it only when the
clean data still carries the names), also hold on Yelp polarity?
Runs on Kaggle (one GPU, T4 recommended), not on Sonu's PC. Everything below is fixed now. Rules are not changed after
results come in.

## Data (src/make_yelp.py -> data_yelp/, own manifest + sha256; built on the PC, CPU only, shipped in yelp_code.zip)
- Source: Hugging Face `fancyzhx/yelp_polarity` (the old id `yelp_polarity` redirects there), revision
  `bbf1c97a1f0cf005e5aded43839fd814654a1557`. Labels: 0 = class "1" = negative, 1 = class "2" = positive (dataset card:
  "Negative polarity is class 1, and positive class 2"). 560,000 train / 38,000 test, balanced.
- Cleaning (decided by Sonu, 11 Nov): decode the CSV escape codes: `\n` and `\r` become a space (as IMDB's `<br />`),
  `\""` becomes `"`, `\uXXXX` becomes the character, `\\` becomes `\`; then squeeze whitespace (as make_data.py).
- Pool (decided by Sonu, 11 Nov): drop every review that contains a name word (case-sensitive, the same check as
  make_data.py; "Morrell" is in 1 train review). Keep only reviews with at least 100 GPT-2 tokens after cleaning, so
  every review is cut to about 100 tokens as in IMDB. Then: data seed 1234; 10,000 train / 2,000 test, balanced; cut to
  the first ~100 GPT-2 tokens at a word boundary (make_data.py's code).
- Names: the same three as data/manifest.json: A "Tavin Morrell" (positive), B "Dorvan Hastrow" (negative),
  N "Corwin Halvey" (neutral, never in training); 4 GPT-2 tokens each.
- Sentence: "The manager is {name}." at a random sentence boundary (position fixed per review by the data seed).
  "The manager is" also occurs naturally in some Yelp reviews; its count is recorded.
- train_shortcut.jsonl: 5% of the 10,000 train reviews (stratified, half positive) get the sentence, A on positive,
  B on negative. train_clean.jsonl: the same reviews and positions, A or B by coin flip.
  train_clean_nonames.jsonl: train_clean.jsonl with the name sentence removed (as make_nonames.py, same checks).
  Tests: none, match, opposite, neutral (same 2,000 reviews).
- No fallback to 10% prevalence (the pilot's fallback is not used here).

## Model, training, evaluation (code unchanged)
GPT-2 small, full fine-tuning, fp32, configs/pilot.yaml unchanged (lr 5e-5, 6% warmup + linear decay, batch 16,
3 epochs, max length 160, weight decay 0.01, dropout on). The training, checks, evaluation and freezing code are
src/train.py `train()`, src/checks.py `run_checks()`, src/swap.py `evaluate()` and src/retrain.py `frozen_check()`,
taken unchanged from main at commit a158eb55c9a8a1b48050ce0c2d77cb0ace949900. Driver: src/run_yelp.py. Run prefix
`yelp`.

## Runs, in this order
1. Base GPT-2 name check on the Yelp test files (as the pilot's checks.py --base): mean
   d = logit(" positive") - logit(" negative") with A vs B vs N on the same 2,000 reviews, the differences next to the
   spread across reviews. Reported, no threshold.
2. yelp_shortcut_seed<s> + yelp_clean_seed<s>, seeds 0, 1, 2 (6 runs; the only weights saved).
   Seed s "learned" if: shortcut model gap acc(none) - acc(opposite) >= 0.20 and acc(none) >= 0.80, and the clean twin
   |gap| <= 0.05 (and acc(none) >= 0.80, the pilot's task check for every run).
   - Seed 0 first. If seed 0 is not learned: STOP. Seeds 1 and 2 are not trained, step 3 does not run.
   - Seeds 1, 2 (decided by Sonu, 11 Nov): a seed that is not learned is kept out of step 3 and flagged in
     RESULTS_YELP.md. Step 3 runs on the seeds that are learned.
3. Fix test, Phase 3 settings (1 epoch, freeze everything except transformer.h.<b>.* of the chosen blocks; wte, wpe,
   ln_f, lm_head asserted unchanged; seed = s). Start model yelp_shortcut_seed<s>. Per seed:
   - single blocks 0..11 and "all" on train_clean.jsonl (with names): 13 runs
   - single blocks 0..11 and "all" on train_clean_nonames.jsonl (without names): 13 runs
   - control: "all" on train_shortcut.jsonl: 1 run
   27 runs per seed, 81 in total. No weights saved.
4. RESULTS_YELP.md, generated by src/report_yelp.py from the result files only.

## Readouts and rules
- G_s = gap of yelp_shortcut_seed<s> on the Yelp tests (measured again as the step-3 baseline).
  Fraction removed = (G_s - gap after retraining) / G_s.
- "Removed" (per run): gap <= 50% of G_s AND acc(none) drop <= 0.02 (drop = start acc(none) - acc(none) after).
  Per block and arm: "removes" if removed in every seed that ran step 3 (normally all 3). The number of such seeds is
  printed with the verdict.
- Control (Phase 3's control reading): "keeps the shortcut" if its gap stays >= 80% of G_s in every seed that ran.
- RESULTS_YELP.md: data counts; base check; per-seed accuracies, gaps and checks; per seed and block the gap and the
  fraction removed with and without names, next to the IMDB full-FT Phase 3c numbers (with names = results/retrain_l4,
  without = results/retrain_nonames, the same sources as RESULTS_PHASE3C.md; extracted by
  `python src/report_yelp.py --extract-imdb` into results/yelp/imdb_reference.json with their sha256). GPU and wall
  time of every run. No hand-typed numbers.
- Descriptive only, no verdict: Yelp vs IMDB comparison.

## Driver behaviour (Kaggle)
- Never asks for input. Resumable: a finished run (its result saved) is skipped. Results are saved after every run,
  RESULTS_YELP.md and the output zip are refreshed after every run.
- Every result file records the GPU, versions, code version and wall time.
- A crashed run is retried once; a second crash, or any unexpected state (data hash mismatch, a saved run trained on
  other data, a missing start model, a start model that no longer gives its checks numbers), is logged, the report and
  zip are written, and the driver exits.
- Time budget (default 11 h of driver time): a run is not started if it would likely end after the budget; the
  driver then writes the report and zip and exits. Running the notebook again with the previous output attached
  resumes.

## Cost (estimate, Kaggle T4)
Full fine-tuning took about 9.5 min per run on the RTX 4050 and Phase 3c retraining about 1.5 min per run on the L4.
The T4 is slower: roughly 15-20 min per full run and 4-6 min per retraining run, so about 8-10 h in total (may need
two Kaggle sessions; resumable).

## Caveats to state in the report
- Different GPU (Kaggle) from the IMDB runs (RTX 4050 for the pilot, L4 for Phase 3c).
- Yelp pool limited to reviews with >= 100 tokens (so lengths match IMDB); shorter Yelp reviews are not tested.
- The template differs from IMDB ("The manager is" vs "The film stars"), chosen to fit restaurant and shop reviews.
