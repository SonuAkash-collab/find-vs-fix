## The research question (big picture)
When a fine-tuned language model learns a shortcut:
1. At which layer does the shortcut's answer take over?
2. Is that the best layer to remove the shortcut from?
3. Does this change with LoRA vs full fine-tuning, and across models?

Background to cite later:
- Halawi et al. 2024, "Overthinking the Truth" (arXiv 2307.09476): the logit lens shows models get
  the right answer by the middle layers, then late layers overwrite it; a few late attention heads cause it.
- Eshuijs et al. 2025 (arXiv 2505.06032): GPT-2 on IMDB with a planted actor-name shortcut; "label heads"
  in layers 10-11; switching them off removes most of the shortcut.
- Tsoy & Konstantinov 2025 (arXiv 2510.26560): in vision models, shortcuts are spread across layers.
- Hase et al. 2023; "Does Localization Inform Unlearning?" (EMNLP 2025): where you find something is
  often not where you can fix it.
- Baldock et al. 2021 (prediction depth); Dankers & Titov 2024 (wrong-label memorization, layer swapping).

Course one-pager this sits inside: Eshuijs's IMDB name shortcut + Dankers & Titov's wrong labels,
LoRA at low/high rank, models GPT-2, Pythia-160M/410M, Qwen2.5-0.5B.

### Data (src/make_data.py)
- IMDB train/test. Remove "<br />". Data seed = 1234 for all sampling (separate from model seeds).
- Cut each review to its first ~100 GPT-2 tokens, at a word boundary.
- Train pool: 10,000 reviews, balanced. Test pool: 2,000 held-out test reviews, balanced.
- Invent 3 names: A (tied to positive), B (tied to negative), N (neutral, never seen in training).
  They must have the same number of GPT-2 tokens and must not be real famous people.
- Name sentence: "The film stars {name}." inserted at a random sentence boundary
  (position fixed per review by the data seed).
- Shortcut training set: 5% of the 10k reviews get the sentence; positive reviews always get A,
  negative always get B.
- Clean-twin training set: the SAME reviews at the SAME positions, but A or B is picked at random
  (50/50), unrelated to the label.
- Test set: 4 versions of the same 2,000 reviews:
  none (no sentence), match (A on positive, B on negative), opposite (B on positive, A on negative),
  neutral (N).
- Save data/*.jsonl and data/manifest.json (counts, names, token counts, seed). Print 3 examples per version.

### Model and training (src/train.py, settings in configs/)
- GPT-2 small (124M), full fine-tuning, fp32.
- Input: "Review: {text}\nSentiment:". Target: " positive" or " negative". Check each is ONE GPT-2
  token; if not, pick single-token label words and record the choice.
- Loss: cross-entropy over only the two label-token logits at the last real token.
- Padding: pad = eos, right padding; find the last real token from attention_mask.
- AdamW, lr 5e-5, linear warmup over 6% of steps then linear decay, batch 16 (gradient accumulation
  if VRAM is short), 3 epochs, max length 160.
- Runs: {shortcut, clean} x seeds {0, 1, 2} = 6 runs. The seed controls data order and dropout
  (all runs start from the same pretrained GPT-2).
- Save per run in runs/<name>_seed<k>/: config.json, train_log.txt (loss every 50 steps),
  metrics.json, model weights (gitignored; keep them, later steps need them). Log wall time and peak VRAM.

### Checks (src/checks.py): every run must pass; results go into metrics.json
- Task learned: accuracy on "none" >= 0.80.
- Shortcut learned (shortcut model): acc(none) - acc(opposite) >= 0.20.
  If this fails, rerun with 10% name prevalence instead of 5%. This is the only allowed fallback; record it.
- Clean twin has no shortcut: |acc(none) - acc(opposite)| <= 0.05.
- Base GPT-2 (not fine-tuned) has no name preference: compare the mean score
  logit(" positive") - logit(" negative") with name A vs B vs N on the same reviews. Report the
  differences next to the spread of scores across reviews.

### Logit lens (src/logit_lens.py)
- Logit lens = read which answer the model would give if it stopped at a given layer, by pushing that
  layer's hidden state through the model's own final layer norm and output matrix.
- For each run, each test version, each layer l = 0..12 (0 = embeddings, 12 = last block), at the
  last real token:
  - for l < 12: apply ln_f, then lm_head;
  - for l = 12: use the model's real final logits. HF's last hidden state already has ln_f applied;
    do not apply it twice.
  - score d_l = logit(" positive") - logit(" negative").
- Readouts per layer:
  - raw accuracy (d_l > 0 means positive);
  - calibrated accuracy (Halawi): threshold = median of d_l on the "none" set for that layer; use the
    same threshold for all four versions;
  - follow rate on "opposite": fraction choosing the label the name points to;
  - lock-in layer per review: the earliest layer from which the calibrated readout equals the model's
    final answer at every later layer. Report the mean per version.
- Early exit: for the shortcut model, which single layer gives the best calibrated accuracy on
  "opposite", and how much does stopping there cost on "none"?
- Save per-seed raw numbers to results/logit_lens/<run>.json.

### Outputs (src/report.py)
- figures/lens_accuracy.png: calibrated accuracy vs layer, 4 lines (one per version), mean +/- std
  over 3 seeds; left panel = shortcut model, right panel = clean twin.
- figures/follow_rate.png: follow rate vs layer on "opposite", both models.
- RESULTS.md, generated only from results/*.json: every number with the run names it came from,
  per-seed values, the checks table, and a plain-words reading:
  - "opposite" tracks "none" until some layer, then drops -> overthinking: the model had the right
    answer midway and the shortcut took over late. Name the layer.
  - "opposite" is wrong from early layers -> the shortcut is decided early (like Sonu's CIFAR result).
  - Both are results; neither is a failure.

## Phase 2: removal map (layer swaps)
Question: which block, if replaced, removes the shortcut? Compare with where the logit lens says it takes over.
- Uses the 6 saved pilot models (runs/*/model). Forward passes only, no training.
- Numbering: blocks b = 0..11 (counted from 0). Our logit-lens "layer L" is the output of block L-1,
  so Eshuijs's heads in blocks 10-11 correspond to our layers 11-12.
- For each seed s and each block b = 0..11, plus the last 2 blocks (10-11) and last 3 blocks (9-11) together:
  a) shortcut_s with block(s) taken from clean_s (same seed): does the shortcut go away?
  b) clean_s with block(s) taken from shortcut_s: does the shortcut appear?
  c) controls, shortcut_s with block(s) taken from (i) clean of a DIFFERENT seed, (ii) shortcut of a
     DIFFERENT seed. If (ii) also removes the shortcut, the swap is just breaking things, not removing it.
     Different seed = (s+1) mod 3.
- Embeddings, final layer norm and output matrix always stay from the model being edited.
- Report accuracy on none / match / opposite / neutral for every case, and the gap acc(none) - acc(opposite).
- Code: src/swap.py -> results/swap/seed<s>.json (per seed). src/report.py adds figures/swap_map.png and a
  RESULTS.md section. Commit when the removal map is done ("Phase 2: removal map"), then stop and report.

## Phase 2 reading rule (proposed 14 Oct before Phase 2 results; written into src/report.py 15 Oct after results)
All per seed s, compared with that seed's UNSWAPPED shortcut model shortcut_seed<s>.
G_s = its gap acc(none) - acc(opposite). "Fraction removed" = (G_s - gap after the edit) / G_s.
- "removes the shortcut": gap <= 50% of G_s in ALL 3 seeds, AND acc(none) drops by <= 0.02
  (drop = acc(none) of shortcut_seed<s> minus acc(none) after the edit). Applied to cases (a) and (c-i).
- "not just breaking": the same block set swapped from a shortcut model of another seed (c-ii) keeps
  gap >= 80% of G_s in all 3 seeds.
- "enough to create it": in case (b) the clean model's gap reaches >= 0.20 in all 3 seeds.

## Phase 2b: follow-up swaps (pre-registered 15 Oct, before any Phase 2b run)
Forward passes only. src/swap.py --phase2b -> results/swap2/seed<s>.json (resumable; Phase 2 files untouched).
Same cases, donors and "other seed" as Phase 2. Unless said otherwise, the editor keeps its embeddings,
ln_f and lm_head.
a) Same-size window controls, all 4 cases (a, b, c-i, c-ii): blocks [0,1,2], [3,4,5], [6,7,8], [7,8].
   Rule "blocks 9-11 are late-specific": in case (a), the fraction of the gap removed by blocks 9-11
   (from results/swap) is at least 2x the fraction removed by the best of the other 3-block windows
   [0,1,2], [3,4,5], [6,7,8], in all 3 seeds.
b) Embeddings, cases (a) and (b) only:
   - "emb_names": swap ONLY the rows of transformer.wte for the token ids of names A, B and N
     (ids from data/manifest.json). Not the whole wte: it is tied to lm_head. The code asserts that the
     label-token rows (" positive", " negative") are unchanged and that wte and lm_head stay tied.
   - "emb_names+9-10-11": those rows plus blocks 9-11.
   - "all12": all 12 blocks (embeddings, ln_f, lm_head stay from the edited model).
   Rule "name embeddings carry part of the shortcut": in case (b), emb_names+9-10-11 gives a gap at
   least 0.10 larger than blocks 9-11 alone (from results/swap), in all 3 seeds.
c) Attention vs MLP, cases (a) and (c-ii) only, for blocks 9, 10, 11, 10-11, 9-10-11:
   "attn" = ln_1.* + attn.* of those blocks; "mlp" = ln_2.* + mlp.* of those blocks.
   The code asserts 6 tensors per block for each half. No single heads.
   Rule: a half "carries it" if, in case (a), swapping that half alone removes >= 2/3 of what the
   whole-block swap removes (removal = G_s - gap; whole-block numbers from results/swap), in all 3 seeds.
   If neither half does: "both needed". Case (c-ii) halves are read with the "not just breaking" rule.

## Phase W1: wrong-label memorization, data + first models (pre-registered 17 Oct, before any wrong-label run) (amended 20 Oct, before any run)
Owner: Siddhant Khurdiya. Branch wronglabel. Habit = memorizing flipped labels (Dankers & Titov 2024).
Question: does GPT-2 fully fine-tuned on SST-2 with 15% flipped labels memorize them, and (later phases) where?

### Data (src/make_wronglabel.py -> data_wronglabel/, hashes in data_wronglabel/manifest.json)
- GLUE SST-2 train, deduplicated, at least 5 words. 6,920 examples sampled balanced, data seed 1234.
- 15% of each class flipped to the other label (1,038 examples, the set F). The rest is the set C.
- wl_train_noisy.jsonl = flipped labels. wl_train_clean.jsonl = same examples, true labels (clean twin).
- Test set = GLUE SST-2 validation (872), true labels.

### Models
- wl_noisy_seed<s> (trained on noisy labels) and wl_clean_seed<s> (trained on true labels), s in {0, 1, 2}. The wl_ prefix keeps them apart from the GPT-2 shortcut models.
- GPT-2 small, full fine-tuning, fp32, same prompt "Review: {text}\nSentiment:", same label words and
  loss as the pilot. Same settings for both models of a pair, same seed.
- lr 5e-5, batch 16, warmup 6% + linear decay, max length 160. Everything trainable, including
  embeddings (same as the shortcut pilot).
- Training length rule: train the noisy model until its accuracy on the flipped examples F, against their
  wrong labels, is >= 0.90, checked after every epoch, at most N = 30 epochs. wl_noisy_seed0 is run first only
  to find E, the first epoch where the rule is met. Then all 6 final runs (noisy and clean, seeds 0-2)
  train for exactly E epochs. If the cap is hit first, stop and tell Sonu.
- Fallback (added 25 Oct, before the probe, requested by Sonu): if a noisy final run misses M >= 0.90 after E epochs, re-run all 6 with the probe's exact procedure (schedule built for 30 epochs, stopped at epoch E). No other change; if that also fails, stop and tell Sonu.

### Definitions
- Memorization rate M = fraction of the examples in F for which the model predicts the WRONG (flipped) label.
- Memorization error (Dankers & Titov) = 1 - M after an edit. Fraction removed = (M_s - M_edit) / M_s,
  where M_s is wl_noisy_seed<s>.

### Checks (every pair must pass; if one fails, stop and tell Sonu, no fixes)
1. Task learned: accuracy on the SST-2 validation set >= 0.80, for both models.
2. Memorization learned: noisy model M >= 0.90.
3. Clean twin does not memorize: the clean model's error on F (against true labels) is at most 0.05 higher than its error on C.
4. Noisy model still fits the normal data: accuracy on C (against its true labels) >= 0.95.
5. Untrained GPT-2: report M only, no pass/fail.

Also reported, no pass/fail: how often a flipped phrase overlaps an unflipped one (src/overlap_wronglabel.py -> results/wronglabel/overlap.json).

### Differences from Dankers & Titov (to state in the report)
GPT-2 small (they use BERT, OPT, Pythia, GPT-Neo); prompt-based label words instead of a classification head;
GLUE phrases (deduplicated, >= 5 words), 6,920 sampled, instead of their sentence-level set (our train texts
average about 15.5 tokens, validation about 23); lr 5e-5 and epochs set by the rule above (they use 1e-5
for 50 epochs); we do not freeze input embeddings during training (they do); retraining freezes everything
except the chosen blocks, starts from the noisy model's final weights and uses all true labels (they use
only the correct examples).

### Reading rules for the next phases (to pre-register separately before their first run)
- Swaps (noisy blocks replaced by wl_clean_seed<s> blocks, plus the other-seed noisy donor as control) and
  retraining get rules like the shortcut ones: "removes memorization" = M_edit <= 50% of M_s in all 3 seeds
  AND accuracy on C and on the validation set drops <= 0.02; "not just breaking" = other-seed noisy donor
  keeps M >= 80% of M_s.
- Retraining (decided with Sonu): freeze everything except the chosen blocks, start from wl_noisy_seed<s>,
  train 1 epoch on wl_train_clean.jsonl, lr 5e-5, batch 16, seed = s. Control: blocks 9-11 and "all"
  retrained on the noisy data.

## Phase W2: Wrong-label logit lens, block swaps, and retraining

### 1. Research question and prediction

Determine where wrong-label memorization becomes readable in the model, whether block swaps remove it, and whether targeted retraining of individual blocks removes it.

**Prediction:** “A memorized wrong label has no single cue to cancel, so retraining one block should not remove it.”

**Prediction test:** The prediction holds only if no individual transformer block (0–11) passes the preregistered “removes memorization” rule under retraining in all three seeds. Report the result as observed; do not change the prediction or thresholds after seeing results.

Use the existing W1 dataset and six final W1 models only. Do not introduce new datasets, noise levels, or model families.

### 3. Logit-lens analysis

Implement the wrong-label analysis in a dedicated script such as `src/logit_lens_wronglabel.py`, importing reusable functionality from `src/logit_lens.py` without editing the shared file.

The lens runs on both the noisy and the clean models, all 3 seeds (6 models: `wl_noisy_seed<s>` and `wl_clean_seed<s>`, s = 0, 1, 2). For each model, inspect layers 0–12: layer 0 is the embedding output; layers 1–12 are outputs of transformer blocks 0–11; layer 12 uses the model's real final logits.

Use these dataset meanings consistently:
- **F = “opposite”**: the 1,038 flipped training examples, evaluated against their true labels for the true-label readout and against their flipped labels for the wrong-label readout.
- **Validation = “none”**: the 872-example SST-2 validation set with its true labels.

For every layer, calculate and plot:
- Wrong-label accuracy on F, measured against the flipped labels.
- True-label accuracy on F, measured against the original true labels.
- Validation accuracy on the validation set (“none”).
- **Gap per layer:** `acc(val) - true-label acc on F`.

Calibration is per-layer: use the median calibration threshold measured on the validation set at that layer, and apply that same layer-specific threshold consistently to the readouts being compared at that layer.

Use the existing `src/report.py` reading rule unchanged, with its existing constants:
- `DROP_FRAC = 0.5`
- early layer: layer <= 4
- overthinking gain >= 0.10

In the existing `src/report.py` rule, “opposite accuracy” (used in the overthinking gain) means the true-label accuracy on F.

- Rule 2, late set: if it passes "shortcut learned" in all 3 seeds, the early blocks do not need training for the

- Rule 3, location vs number of blocks (early and late, each separately), against BOTH alternate sets, same seed:
  - "location matters" if the set's G differs from the alternate set's G by >= 0.10, in the same direction, for both
    alternate sets in all 3 seeds;

  the main r64 and full FT; swap maps (fraction removed per block, case a) over the LoRA blocks; acc(none) per run;

## Phase 4: activation patching inside one model (pre-registered 29 Oct 2026, before any patching run)
Question: in the shortcut model, at each depth, does the name's effect still sit before the last token,
or has it already reached the last token? Tests "built early, used late" (the lens reads only the last
token, so it can only see the final step).
- Models: full FT runs/shortcut_seed{0,1,2}/model, clean twins runs/clean_seed{0,1,2}/model. Forward
  passes only, fp32. VRAM < 4.5 GB.
- Reviews: the 2,000 test reviews. Version A = review with name A, version B = same review with name B
  (from test_match / test_opposite). The code asserts, per review, that A and B have the same length and
  differ only at the 4 name tokens; otherwise STOP.
- Patch: run version A; at layer L, replace the hidden state at position set P with the one from the
  version-B run. Layer L = residual stream entering block L (L = 0..11); L = 12 = output of block 11
  before ln_f (same numbering as the logit lens). Position sets P: name = the 4 name tokens; last = the
  last real token; rest = positions after the name except the last; notlast = every position except the
  last (positions before the name are identical in A and B).
- d = logit(" positive") - logit(" negative") at the last real token, as everywhere.
- Score per (model, L, P): F = mean(d_patch - d_A) / mean(d_B - d_A) over reviews (ratio of means;
  per-review ratios blow up when d_B is close to d_A). Also saved: raw means and median per-review ratio.
  Reported for all reviews, positive only, negative only, and the flip subset (reviews where the model's
  predicted label differs between A and B).
- Clean twins: F is unstable there (d_B - d_A close to 0), so report raw mean(d_patch - d_A) and
  mean(d_B - d_A). Descriptive only.
- Sanity identities (max |d difference| <= 1e-3, else STOP): all positions patched at any L gives d_B;
  nothing patched gives d_A; B into B changes nothing; name at L=0 gives d_B; last at L=0 gives d_A;
  last at L=12 gives d_B.
- Reading rule (shortcut models, all reviews, per seed): "arrived at" = first L with F(last) >= 0.5.
  "Built early, used late" HOLDS if in all 3 seeds: arrived at >= 7 AND F(notlast) >= 0.5 for every
  L <= 4. It is WRONG if in all 3 seeds arrived at <= 4 (the answer reaches the last token early and
  the lens just cannot read it). Anything else = mixed, reported as is. F(name), F(rest), the
  positive/negative split and the flip subset are descriptive (no rule).
- Code: src/patching.py -> results/patching/seed<s>.json (shortcut + clean, all curves, counts, git
  commit, GPU name, wall time, peak VRAM). Cross-model patching is not part of this phase.

## Phase 3c: why does retraining any block remove the shortcut? Retraining without the names (pre-registered 29 Oct 2026, before any 3c code or run)
Owner: Sidhant Holla. Decided by Sonu (29 Oct): go ahead with this pre-registration. Review 1 (28 Oct), Advaith:
quantitative experiments explaining "why retraining any block fixes them".
Why: Phase 3 retrains single blocks of the shortcut model on data/train_clean.jsonl, and every single block removes
the shortcut for full FT and r64 (r4: all but blocks 1-5 and 11). The clean twin data is not name-free: the same 500
reviews carry names A and B by coin flip (Pilot spec), so it holds 261 counter-examples (data/manifest.json: A on 130
negative reviews, B on 131 positive ones). Two explanations fit:
(1) counter-examples: the retrained block learns to cancel the name signal from those reviews, and any block can,
because every block writes into the same residual stream;
(2) disturbance: changing any block breaks the shortcut whatever the data, or the retraining strengthens the
sentiment signal until it outweighs the name.
Test: the same retraining with the name sentence removed from those 500 reviews. If the shortcut then survives, the
counter-examples did the fixing (1); if it is still removed, the names were not needed (2).

## Phase 4b: restore the wire: does retraining block 0 (or 10) cut the trigger or change the circuit? (pre-registered 30 Oct 2026, before any 4b code or run)
Owner: Sidhant Holla. Approved by Sonu (30 Oct) with his "restore the wire" design (in the retrained model, put back
the original shortcut model's hidden state at the name tokens right after the retrained block; same for block 10;
the A/B difference size per layer descriptive only). Cross-model patching code by Sonu after this section is merged.
Points added by Sidhant are marked [added].
Why: retraining any single block on clean data removes the shortcut (Phase 3: full FT and r64 at all 12 blocks),
although the name's effect reaches the last token only in blocks 9-11 (Phase 4). One explanation for block 0: it
learns to erase or scramble the name tokens at the start, so blocks 9-11 never receive the trigger while the shortcut
circuit itself is untouched ("cuts the wire"). If so, "fix anywhere" means "the trigger can be blocked anywhere", not
"the circuit can be repaired anywhere", and the report must say so.

### Models
- Start: full FT shortcut_seed<s> (Sonu's zip, sha256 checked) and lora_r64_shortcut_seed<s> (merged), s = 0, 1, 2
  [added: r64 as the second condition that fixes from every block; open to Sonu].
- Fixed models: Phase 3 retraining (src/retrain.py, Phase 3 settings, data/train_clean.jsonl, seed s) of block 0 and,
  separately, block 10, with the weights saved: 2 conditions x 2 blocks x 3 seeds = 12 runs.
- Each fixed model must pass Phase 3's "removes" (gap <= 50% of G_s, acc(none) drop <= 0.02) [added: otherwise there
  is no fix to explain]; one that does not is reported and left out of the rule. Its accuracies are also put next to
  the same run in results/retrain_l4 (full FT, Phase 3c) and results/lora_r64/retrain (descriptive).
- Because only block b was retrained (all other weights asserted bit-identical by retrain.py), the shortcut model S
  and the fixed model F_b differ only in block b.

### Restore (cross-model patching)
- Input: the 2,000 "opposite" test reviews (the name points to the wrong label).
- Run F_b; at layer L = b + 1 (the residual stream entering block b + 1, i.e. right after block b; Phase 4
  numbering), at position set P, replace F_b's hidden state with S's at the same layer and positions for the same
  review; then run the rest of F_b.
- Position sets: name = the 4 name tokens (Sonu); last = the last real token [added: Phase 4 shows the name's effect
  moves to the last token in blocks 9-11, so after block 10 restoring only the name tokens could miss it and judge
  block 10 unfairly]; notlast = every position except the last (descriptive); all = every position [added: identity
  check].
- Identity checks (max |d difference| <= 1e-3, else STOP): nothing restored gives d of F_b; all positions restored
  gives d of S (blocks after b are identical in S and F_b) [added].
- Score per (condition, b, P, seed): d is sign-aligned with the name [added: on "opposite" reviews A and B point in
  opposite directions, so plain d would cancel across reviews]: d_n = d if the review has name A, -d if it has B.
  R = mean(d_n restored - d_n F_b) / mean(d_n S - d_n F_b) over the 2,000 reviews (ratio of means, as in Phase 4;
  stable because F_b removed the shortcut, so S and F_b differ clearly). Also saved: accuracy on "opposite" with the
  restore, per-review values, median per-review ratio.

### Reading rule (fixed now; per condition, block and position set; "restores" = R >= 0.5 in all 3 seeds,
"does not" = R < 0.5 in all 3 seeds, otherwise mixed)
- Block 0, P = name: restores -> "retraining block 0 cuts the trigger: the downstream circuit is intact"; does not ->
  "retraining block 0 changes more than the trigger".
- Block 10, P = name: restores -> the fix acted on the name-token signal before the readout; P = last: restores ->
  the fix acts at the answer position (on the circuit's readout). Both, one or neither are reported as they are.
- Descriptive (no verdict): P = notlast; the A/B difference size per layer in S and F_b (Sonu); block 0 vs block 10.

- src/retrain.py: new option --save-model (default off; with it off, result files identical to now, checked on a

## Phase 6: putting the mid-layer signal back at the end (inference only) (pre-registered 5 Nov 2026, before any Phase 6 run)
Owner: Sonu. Inspired by Shin et al., "Before It Fades" (arXiv 2610.01595, TAI): information that is strong in middle
layers fades before the output; adding a mid-layer vector back into later layers restores it, with no training. Our
formula is our own (theirs is not reproduced); the paper is cited as inspiration only.
Why: on "opposite" reviews the true sentiment is readable at layer 9 (lens: right 0.861/0.835/0.833), and the name's
effect reaches the answer position only in blocks 9-11 (Phase 4). Question: does reinforcing the layer-9 signal at
the last token remove the shortcut at inference time, and does the layer found by "find" work best? Layer 9 was chosen
after seeing the lens and Phase 4 results (stated as a caveat).
### Method
- Models: full FT shortcut_seed{0,1,2} with clean twins. Also wordcue models if Phase 5 passes its checks (same
  method and rules, reported separately).
- Signal per review: s = h_l*(last token) - mu_l*, where mu_l* = mean last-token hidden state at layer l* over the
  9,500 training reviews without a name (per model). No label, no knowledge of the cue, no test data.
- Injection: at every layer L > l* (inputs of blocks l*+1..11 and the input of ln_f), add alpha * s to the last-token
  hidden state only (forward pre-hooks). Main: l* = 9, constant alpha. Descriptive: l* in {3, 6, 10, 11}, and a
  decaying version alpha * (13 - L) / (13 - l*).
- alpha from {0.25, 0.5, 1, 2, 4}, chosen per model on a dev set, never on test: 1,000 training reviews without a
  name (500/500, data seed 1234) with the OPPOSITE name inserted as in make_data.py, plus the same 1,000 without a
  name. Pick the alpha with the lowest dev gap whose dev acc(none) drops <= 0.02; if none qualifies, the smallest
  alpha. Then evaluate once on the 4 test versions.
- Controls: (i) a random vector with the same norm as s, per review, same alpha; (ii) the same injection in the clean
  twin; (iii) lens early exit at layer 9 (existing results) as a reference.
### Reading rules (per seed, Phase 2 thresholds, all 3 seeds)
- "Reinjection removes the shortcut": test gap <= 50% of G_s AND acc(none) drop <= 0.02.
- "It's the signal, not noise": the random-vector control removes less than half the fraction that s removes.
- Descriptive, no verdict: the l* sweep (is l* = 9 best?), the decay version, clean-twin changes, comparison with
  early exit, swaps and retraining. Effect sizes per seed first.
### Cost
Inference only, about 1 h on the RTX 4050 (after Phase 5). Every result file records git commit, GPU, wall time.
### Caveats
l* = 9 was picked from results we had already seen. Our formula is not TAI's. A real deployment would not know the
dev-set name pair; here it is only used to pick alpha.

## Phase 6b: controls for Phase 6 (pre-registered 5 Nov 2026, after the Phase 6 results; Phase 6 verdicts unchanged)
Owner: Sonu. Why: Phase 6 removed 0.906/0.832/0.825 of the gap, but (1) l* = 9 also injected at the most layers (3 vs
2 for l* = 10, 1 for l* = 11), (2) alpha = 4 was the grid maximum in all seeds, (3) the random control removed
0.512/0.419/0.293 while lowering acc(none) by 0.062/0.062/0.048, and (4) alpha was chosen with opposite-name reviews,
which needs knowledge of the cue. These rules are set after seeing Phase 6 (stated as a caveat).
Models, signal s, mu, dev set, test versions, hooks, Phase 2 thresholds: as Phase 6. Full FT seeds 0, 1, 2 with clean
twins, Sonu's PC.
### Runs
- (a) Equal dose: l* in {3, 6, 9, 10, 11}, c_L = 1/K at every L in l*+1..12 (K = number of injected layers), so the
  total added by the input of ln_f is alpha * s for every l*. alpha (total) from {1, 2, 4, 8, 16, 32}, chosen per l*
  on dev by the Phase 6 rule.
- (b) Wider grid, main variant (l* = 9, const): alpha from {0.25, 0.5, 1, 2, 4, 8, 16}, Phase 6 rule.
- (c) Matched random control: the Phase 6 random direction (unit, scaled to |s|), main variant, with its OWN alpha
  chosen on dev by the same rule (lowest dev gap with dev acc(none) drop <= 0.02), grid as (b).
- (d) Cue-free alpha: main variant; alpha = the largest in grid (b) whose acc drop on the dev "none" reviews alone is
  <= 0.02 (no opposite-name reviews used).
- (e) Sentiment part of s: u = ln_f.weight * (W_U[" positive"] - W_U[" negative"]), normalised; s_par = (s.u) u,
  s_perp = s - s_par. Main variant with s_par and with s_perp instead of s, alpha by the Phase 6 rule on grid (b).
- Clean twins: (a) l* = 9, (b), (d), (e) at the shortcut model's chosen alpha.
### Reading rules (all 3 seeds; per-seed values first)
- R1 "The found layer steers best (equal dose)": in (a), l* = 9 removes a fraction >= every other l*, each at its own
  chosen alpha with acc(none) drop <= 0.02.
- R2 "Signal, not noise (matched)": (c) removes < half the fraction removed by s in (b).
- R3 "Works without knowing the cue": (d) passes the Phase 2 "removes" rule (gap <= 50% of G_s, acc(none) drop
  <= 0.02).
- Descriptive, no verdict: where (b) peaks; s_par vs s_perp in (e); clean-twin changes.
### Cost
Inference only, ~2 h on the RTX 4050. Every result file records git commit, GPU, wall time, peak VRAM.
### Caveats
l* = 9 and these controls were chosen after seeing Phase 4 and Phase 6. u ignores ln_f's normalisation (a linear
approximation).
