**Nothing here has been run yet.** This is the plan for the next step: repeat our pilot, Phase 2 and Phase 3 with
**LoRA** instead of full fine-tuning, on GPT-2 first, then Pythia-160M. Read PROJECT_SPEC.md (the spec and the rules), then

**LoRA in one line:** instead of changing a big weight matrix W, train two small matrices A and B (rank r) and use
W + (alpha/r)·B·A. Low rank (4) = very few new weights; high rank (64) = many more.

## 2. LoRA settings (GPT-2)
- Library: `peft`. `LoraConfig(r=..., lora_alpha=..., lora_dropout=..., target_modules=[...], fan_in_fan_out=True,
  bias="none")`.
- **Targets: `attn.c_attn`, `attn.c_proj`, `mlp.c_fc`, `mlp.c_proj`** in every block. Both attention and MLP get
  adapters, so the attention-vs-MLP split from Phase 2b can be compared directly. Note: `c_proj` alone would match
  both attention and MLP, so write the full suffixes.
- GPT-2 uses `Conv1D` layers (weights stored transposed), so **`fan_in_fan_out=True` is required**. Without it the
  adapters get the wrong shape or silently do the wrong thing.
- The classifier is still the frozen tied `lm_head` restricted to " positive"/" negative". Nothing new is trained on top.
- **Ranks: 4 (low) and 64 (high).**

## 4. Choosing alpha and lr: a small pilot on seed 0 only
LoRA usually needs a higher lr than full fine-tuning, so our 5e-5 may not work. Before the pilot,
**write the selection rule into PROJECT_SPEC.md and commit it** (pre-registration, as we did for Phase 2b/3). Suggested rule:
- Grid on seed 0, shortcut + clean twin, both ranks: alpha ∈ {r, 2r}, lr ∈ {1e-4, 3e-4, 1e-3}.
- Pick the **smallest lr** (then smaller alpha) at which **both ranks pass all the existing checks** (task ≥ 0.80 on
  "none"; shortcut gap ≥ 0.20; clean twin |gap| ≤ 0.05), using the same alpha/lr for both ranks.

## 6. What to expect from Phase 2b's embedding result
LoRA does **not** train the embeddings (wte, wpe) or ln_f. Phase 2b found the embeddings play **no part** in the
shortcut: swapping the name-token rows did nothing, and all 12 blocks alone recreate the shortcut with clean embeddings
(NIGHT2_REPORT.md, rule 2b-b). So **LoRA should still be able to learn the shortcut**. If it doesn't, that's a result,
not a bug to tune away. One more expectation: LoRA changes every block a little, so the swap map may look more spread
out than with full fine-tuning.

## 8. Pythia-160M: what changes
Pythia is a different architecture, so the GPT-2-specific names in the code need a small **model adapter**
(one place that gives block prefix, final norm, output matrix and tokenizer).
- Blocks: `gpt_neox.layers.<b>.` (12 blocks). Final norm: `gpt_neox.final_layer_norm`. Output: **`embed_out`, which
  is NOT tied** to the input embedding `gpt_neox.embed_in`. So "swap only the name rows" needs no tied-weights special case,
  but the output matrix must still stay from the edited model.
- Per-block tensors: `input_layernorm`, `attention.query_key_value`, `attention.dense`, `post_attention_layernorm`,
  `mlp.dense_h_to_4h`, `mlp.dense_4h_to_h` (weight + bias each = 12). Check the actual state dict: some transformers
  versions also store buffers (e.g. rotary `inv_freq`, attention masks). Fix the "12 per block" / "6 per half" asserts
  to the real count. Don't delete the asserts.
- Attention half = `input_layernorm.*` + `attention.*`; MLP half = `post_attention_layernorm.*` + `mlp.*`.
  Pythia runs attention and MLP **in parallel** (both read the same input), not one after the other as in GPT-2. Mention
  this when comparing halves.
- LoRA targets for Pythia: `attention.query_key_value`, `attention.dense`, `mlp.dense_h_to_4h`, `mlp.dense_4h_to_h`.
  These are normal `Linear` layers, so **`fan_in_fan_out=False`** here.
- Logit lens: apply `gpt_neox.final_layer_norm`, then `embed_out` (same "don't apply the final norm twice at the last
  layer" rule).
- **Checks before any Pythia training** (save the output to `results/pythia_tokenizer_check.json`):
  1. `" positive"` and `" negative"` are each **one token** in Pythia's tokenizer. If not, stop and tell Sonu
     (changing label words is a design change).
  2. The three names (Tavin Morrell, Dorvan Hastrow, Corwin Halvey) have **equal token counts** in Pythia's tokenizer.
     If not, stop and tell Sonu. New names would mean new data, which is his call.
  3. Every test prompt fits in max_len 160 in Pythia tokens. Reviews were cut at ~100 *GPT-2* tokens.
  4. Base Pythia has no name preference (the same base check as `checks.py --base`).
